# Team Workflow and Ownership

## Four pairs
1. AI/vision/data
2. Frontend/dashboard/UX
3. Backend/database/evidence
4. Integration/testing/presentation

## Individual ownership
- Lead/integration
- Vehicle detection/tracking
- Event/dataset
- ANPR/image processing
- Backend/evidence
- Dashboard/UX
- Testing/civic research
- Video/PPT/pitch

## Git workflow
Protected `main`; short feature branches; pull request with tests/screenshots; one reviewer from another pair; squash merge.

## Definition of Ready
Problem and user value clear, acceptance criteria written, dependency/data available and owner assigned.

## Weekly rhythm
Planning, pair implementation, integration check, metrics review and demo/rehearsal.

## Communication rule
No member claims a feature is implemented without a working demonstration or merged code. All members use the same terminology and technology status.
